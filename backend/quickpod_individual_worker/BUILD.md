# Building multi-worker Docker images

Multi-worker Dockerfiles use `COPY` paths that are **relative to the build context directory**. That directory must be the folder that **contains every** `worker_*` path referenced in the generated Dockerfile (including `worker_multi_common` and all single-model worker trees such as `worker_qwen_image_edit_2511_rapid_aio`).

## Layout

On your laptop (repo) that directory is:

`backend/quickpod_individual_worker/`

On a QuickPod build host, use `/work_space` (or any directory) with the **same sibling layout** — **the folder name does not matter**, only that all worker directories referenced by `COPY` exist next to each other:

```text
/work_space/
  worker_multi_common/
  worker_flux_klein_9b_multi/
  worker_qwen_image_edit_2511_rapid_aio/
  worker_wan_22_fp8_lightx2v_i2v/
  ... (every path emitted by generate_dockerfile.py)
```

## Commands

From that parent directory (e.g. `/work_space` or `quickpod_individual_worker`):

```bash
# Example: flux multi (after prep_model populated models/ under the multi worker)
docker build -f worker_flux_klein_9b_multi/Dockerfile .

docker build -f worker_qwen_image_edit_2511_rapid_aio_multi/Dockerfile .
docker build -f worker_stable_diffusion_xl_multi/Dockerfile .
docker build -f worker_z_image_turbo_multi/Dockerfile .
docker build -f worker_wan_22_fp8_lightx2v_i2v_multi/Dockerfile .
docker build -f worker_wan_22_fp8_lightx2v_t2v_multi/Dockerfile .
docker build -f worker_hunyan15_480p_i2V_step_distilled_multi/Dockerfile .
docker build -f worker_hunyan15_480p_t2V_distilled_multi/Dockerfile .
```

Do **not** use the multi worker folder alone as context (e.g. `cd worker_flux_klein_9b_multi && docker build .`) unless you also copy every `COPY` source into that tree and adjust paths.

## MiniMax H3 ComfyUI (self-contained)

This image is **not** a multi-worker. The Dockerfile clones ComfyUI v0.37.0 and pinned custom nodes during `docker build` (including SolAttn + Comfy Kitchen + MMH3 Ultimate Upscale for Fast MiniMax H3). Weights are **not** in the image; the container downloads them on first boot (Seed Hunter unet plus MATLOWAI fused turbo INT8). Default `/run` uses `fastMinimaxH3_textToVideo.json` (~0.4 MP). Pass `params.upscale=true` for the Civitai second pass (default 1.0 MP; set `upscale_megapixels` to 0.6–0.9 on OOM). Pass `params.workflow=seed_hunter` for the full Seed Hunter graph.

Build context is the MiniMax worker folder itself:

```bash
cd backend/quickpod_individual_worker/worker_minimax_h3_comfy
# or on a build host: cd /work_space/worker_minimax_h3_comfy

docker build -t pavanalur3/quickpod_worker:minimax_h3_comfy .
docker push pavanalur3/quickpod_worker:minimax_h3_comfy
```

## LTX-2.5 INT8 AllModes ComfyUI (self-contained)

Same pattern as MiniMax H3. The Dockerfile clones ComfyUI v0.37.0, KJNodes, SolAttn_triton, and copies `custom_nodes/ltx25_smart_controls` from this folder. Weights (~40 GB from `Lightricks/LTX-2.5`) download on first boot. SageAttention + Triton are installed at build time for the Stage 1 / Stage 2 Speed path.

```bash
cd backend/quickpod_individual_worker/worker_ltx25_int8_comfy
# or on a build host: cd /work_space/worker_ltx25_int8_comfy

docker build -t pavanalur3/quickpod_worker:ltx25_int8_comfy .
docker push pavanalur3/quickpod_worker:ltx25_int8_comfy
```

## Qwen Image 2.1 Turbo + MiniMax Music 3

Same self-contained pattern. **Build these on GitHub Actions**, not on the Windows laptop and not on Quickpod DIND. See `.github/workflows/README-COMFY-BUILDS.md`.

```bash
# GitHub Actions → Build ComfyUI worker images → worker=all
# Tags:
#   pavanalur3/quickpod_worker:qwen_image_21_turbo_comfy
#   pavanalur3/quickpod_worker:minimax_music3_comfy
```

Qwen uses molbal/ComfyUI-GGUF + Unsloth Q8_0 UNET GGUF (CLIP/VAE stay Comfy-Org). Music 3 is native ComfyUI v0.37.0 with the official `audio_minimax_music_3.json` graph and int8 convrot DiT.

## `worker_multi_common`

This is **not** a separate deployable worker; it is shared Python code copied into each image. It must be present in the build context (commit it in git so CI/rsync includes it).

The file `worker_multi_common/Dockerfile` (if present) is **not** that shared library: it is an optional, self-contained image recipe (e.g. Flux-centric layout with many sibling `COPY`s). **Slim** per-flavor images are built from each `worker_*_multi/Dockerfile` generated by that multi’s `src/generate_dockerfile.py`.
